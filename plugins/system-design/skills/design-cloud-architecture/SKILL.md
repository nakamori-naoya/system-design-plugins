# design-cloud-architecture

要件・利用負荷・品質要求の資料を根拠に、どの配置方式とどのサービスを、何と比べて、どんな得失と障害時の振る舞いで採るかを決め、write-doc の `cloud-architecture` 型で保存する。上流の資料、業務ルール、データモデルは作り直さず、IaC も実装しない。上流に不足や矛盾を見つけたら、自分で埋めずに上流の ID を引いた未決として残す。

配置方式、比べる機能領域、構成図の書き方は [クラウドアーキテクチャの判断](references/architecture-judgment.md) を読む。

## 外しやすい判断

provider は推測しない。`aws` か `gcp` を利用者が明示したときだけ始め、その指定を合意済みの制約（`CON-`）として追跡の表に置く。未指定やほかの値なら、確かめを求めて止まる。

選定には代替案と根拠が要る。構成を左右する領域ごとに、採用候補、一つ以上の代替案、要件・品質・利用負荷・制約のどの ID に基づくか、得るものと失うものを本文で比べる。人気、慣例、プロバイダーの一覧に載っていることは根拠にならない。根拠を補えない選定は採らず、決める問い（`ARC-OQ-`）にする。対象の境界の外にある領域は、外にある理由を一文書いて比べない。

ADR（`### ADR-<番号>: <決めたこと>`）は、選んだこと、比べた候補、根拠、得失、考え直す条件を持つ。利用者が合意したものだけが `agreed_decision` で、未合意なら `hypothesis` のままにする。仮説の ADR や未決が残る資料を、実装へ渡せる決定として書かない。

障害と縮退の経路（`FAIL-`）は、起点のノード、影響、縮退のしかた、検知と復旧を持つ。実負荷試験、障害試験、災害復旧訓練をしていなければ、検証は計画と書く。仕様を読んだことやテストデータは、成功の証拠にならない。

分からないことを推測で埋めない。欠けた情報が構成の結論を変えるなら grill で問うか止まり、変えないなら仮説と明示して進む。

## 問い方

上流の資料と制約を読めば分かることは問わない。答えで配置方式、選定、ADR の採否、障害時の振る舞いが変わる問いだけを、推奨と理由を添えて grill へ渡す。返った決定は根拠として本文へ反映し、未決のまま残ったものは推奨を仮に置いて、選定なら候補のまま、ADR なら仮説のまま書く。既存の資料（`update_target`）を深めるときは、反証する選定か ADR を一つ決め、上流の値や前提が変わったときに崩れないかを当てる。

## 書いて保存し、保存した資料を一回検査する

write-doc に、本文を `material`、`document_type: cloud-architecture`、保存先（`output_directory` と `name`、または `update_target`）として渡す。template の検査が読む目印（追跡の表、ID、状態の値、`flowchart` のブロック）に従う。上流の未決を引き継ぐ行は、上流の ID（例 `QR-OQ-001`）をそのまま使う。

保存した資料を一回検査する。

```bash
python3 scripts/architecture.py check \
  --upstream <要件の資料> --upstream <利用負荷の資料> --upstream <品質要求の資料> \
  < <保存したクラウドアーキテクチャの資料>
```

検査が見るのは、追跡の表と ID の形と状態の値、根拠の ID に届くこと、構成図が一つで追跡の表の全ノードを含むことだけである。失敗したら資料を直して `update_target` で保存し直す。採用した構成が指定の provider のサービスで組まれているか、選定の比べ方が妥当かは、保存した資料を読んで確かめる。

## 止まるとき

provider が `aws` か `gcp` で明示されていない、要件・利用負荷・品質要求の資料のどれかが無い、上流が別の対象システムを指している、論理設計から境界もノードも流れも識別できない、保存先が絶対パスで一つに決まらない、grill・write-doc・検査が失敗した、のどれかで止まり、理由を変えずに返す。依頼の中心が要求の発見、データモデル、アプリケーションの内部設計、IaC の実装なら、この入口の仕事ではないと返す。

## 返すもの

保存した資料の絶対パス、検査が返した `status`（未決の行も仮説の ADR も無ければ `ready`、あれば `unresolved`）、配置方式、採用した選定と退けた代替案、合意済みと仮説の ADR、grill で決まったこと、推奨を仮に置いた未決、まだ実施していない検証を返す。
